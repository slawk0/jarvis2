# Jarvis Server Manager — notes for working in this repo

Desktop app (Tauri 2) that manages Linux servers over SSH. Rust backend in `src-tauri/`,
SvelteKit static SPA (Svelte 5 runes, TypeScript, Tailwind 4, shadcn-svelte, lucide) in `src/`.
Everything in the repo is in English.

## Commands

```sh
pnpm tauri dev                 # run the app
pnpm check && pnpm lint && pnpm test
pnpm bindings                  # regenerate src/lib/ipc/bindings.ts after any IPC change
pnpm docs:ipc                  # regenerate docs/ipc-reference.md after pnpm bindings
cd src-tauri && cargo test && cargo clippy --all-targets -- -D warnings && cargo fmt --check
```

`cargo test` takes one filter. Live tests against `dev/test-server` are `#[ignore]`d:
`JARVIS_TEST_KEY=<private key> cargo test live_ -- --ignored --test-threads=4`.

Use `JARVIS_CONFIG_DIR=<dir>` for every development run so the app does not read the user's
real profiles. Never connect to servers from the real profile list while developing.

## Backend (`src-tauri/src`)

- `lib.rs` registers every command in `specta_builder()` and sets up plugins, tray and state.
- `error.rs`: `AppError { code: ErrorCode, details }`. Commands return `AppResult<T>`. A new
  failure mode gets a new `ErrorCode`; the frontend maps codes to messages in
  `src/lib/ipc/errors.ts` (a missing mapping is a compile error).
- `shell.rs`: `q()` quotes one shell word, `Cmd` builds a command line, `validate::*` checks
  user input (names, paths, ports, cron expressions…). **Every value that reaches a shell goes
  through one of these.** The frontend never sends shell text, except where the feature is
  running the user's own command (Terminal, Runbooks, cron job commands).
- `ssh/session.rs`: `Session` is the one connection to the active server. `exec(Exec)` runs a
  script and returns `Output`; `run`/`run_sudo`/`exec_auto`/`run_auto` are shorthands
  (`*_auto` retries with sudo on "permission denied"). Scripts run as
  `env LC_ALL=C LANG=C sh -c '…'` with a sane `PATH`. Also: `sftp()`, `tunnel()`,
  `lease_stream()` for long-lived channels. The main connection allows 6 concurrent commands.
- `sudo.rs`: the only sudo implementation. `Exec::sudo()` marks a command as needing root; the
  password is written to the channel's stdin for `sudo -S`, cached in memory for 15 minutes,
  and locked for 60 s after 5 wrong attempts. When no password is cached the command fails with
  `SUDO_PASSWORD_REQUIRED` and the frontend prompts and retries.
- `jobs.rs`: long-running commands. `state.jobs.start(app, session, JobMeta, Exec)` streams
  output as `JobOutput` events and ends with `JobDone`; `jobs.spawn` runs a custom async body
  with a `JobCtx` (`stream`, `step`, `note`). Cancelling kills the remote process group.
- `store/`: `profiles` (server list), `profile_data` (one JSON document per profile and
  `DataKey`), `settings`, `secrets` (OS keyring only; names like `db/<id>/password`). Deleting a
  profile deletes its documents and secrets.
- `deps.rs`: the `Tool` enum with a probe and install recipe per package manager;
  `deps::require(session, tool)` fails with `DEPENDENCY_MISSING`.
- One module per domain (`docker/`, `nginx.rs`, `firewall.rs`, `backups.rs`, `restic.rs`,
  `db/`, …). Each keeps its command builders and output parsers as plain functions with unit
  tests next to them, and thin `#[tauri::command]` wrappers at the bottom.
- `pangolin.rs` is an HTTP proxy to the Pangolin API (not SSH); the frontend builds the paths.

### IPC types (specta)

Bindings are generated by `cargo test export_bindings`. Constraints that bite:

- No `serde_json::Value` in IPC types: pass JSON as a `String`.
- No `#[serde(default | alias | flatten | skip_serializing_if)]` on types that derive `Type`.
- `f64` fields need `#[specta(type = i32)]`, otherwise they become `number | null`.

### Secrets

Secrets reach remote programs through the environment or stdin, never through argv or a
world-readable file. Backups and restic send `export NAME='value'` lines on stdin and
`eval "$(cat)"` them; a scheduled backup keeps them in `/etc/jarvis-backups/<id>.env` (mode 600).

## Frontend (`src/lib`)

- `ipc/`: `api.*` wraps the generated commands, opens the sudo dialog on
  `SUDO_PASSWORD_REQUIRED` and retries. `apiQuiet.*` never prompts — use it for polling.
- `state/resource.svelte.ts`: `resource(loader)` (data / error / loading / refresh),
  `autoLoad(res, () => visible, pollMs)`, `poll(...)`, `Busy` for per-row busy state.
  Polling stops while a tab is hidden or the server is offline.
- `services/`: `app` (session, link status), `sudo`, `jobs`, `transfers`, `settings`, `toast`,
  `confirm`/`prompt`, `updater`, `profile-data` (`loadDoc`/`saveDoc` typed per-profile documents).
- `components/`: shared building blocks. Use them instead of new one-offs: `Page`, `SubTabs`,
  `DataTable` (sort, search, select, bulk, context menu, virtualised), `Modal`, `StateView`,
  `Field`, `SelectField`, `LogViewer`, `JobDialog`, `DependencyGuard`, `PathInput`,
  `DirPicker`, `CronInput`, `IpLink`, `RefreshControl`. `components/ui/` is shadcn-svelte
  (generated; excluded from Prettier).
- `workspace/`: `layout.ts` is the pure split-tree engine (unit-tested), `workspace.svelte.ts`
  the store (panes, focus, back stack, cross-tab `request()` bus), `registry.ts` the tab list.
- `features/<tab>/`: one folder per tab. A tab component takes `{ visible, profile }` props,
  loads on first `visible`, and exports `refresh()`.

### Adding a tab

1. Backend module with commands, registered in `lib.rs`; `pnpm bindings`.
2. `features/<tab>/<Tab>.svelte` following the tab contract.
3. An entry in `workspace/registry.ts` (with `requires: [...]` when it needs server tools).

### Svelte gotchas seen in this codebase

- A variable named `state` breaks `$state`. A component must not share its name with a
  `.svelte.ts` module in the same folder.
- A `$derived` that returns the same array or object reference does not notify; return a copy.
- Writing state inside an `$effect` that also reads it loops; wrap the write in `untrack`.
- `{@const}` must be the direct child of a block.

## Conventions

- Destructive actions go through `confirm({ destructive: true })`; the riskiest use
  `typeToConfirm`.
- Wording: "Delete" destroys data on the server, "Remove" only forgets something in Jarvis.
  Sentence case everywhere.
- Parse machine formats (`--json`, `--format`, `-o json`) where a tool offers them.
- No user names, hosts or other personal data in code, tests or fixtures.

## Release

Version in `package.json` → `pnpm version:sync [x.y.z]` → tag `vX.Y.Z` → the Release workflow
builds, signs and publishes. The updater endpoint and public key are in
`src-tauri/tauri.conf.json`.
